# Browser test media

Small synthetic videos used by the Playwright local-player tests. They are read from disk by the tests only; they are not under `public/` or `src/` and are not part of the production build.

They qualify local `<video>` playback of a file on the same device. None of them says anything about Progressive Watch, which the application does not implement, or about any browser's product compatibility, which [COMPATIBILITY.md](../../../../docs/COMPATIBILITY.md) governs.

## WebM fixtures

### Provenance

Both WebM files were generated by [`scripts/generate-test-media.mjs`](../../scripts/generate-test-media.mjs). The script draws every frame from a fixed pattern: a solid background whose color changes each second, one white marker per elapsed second along the top, and a white bar that sweeps across the frame once per second. They contain no recorded, personal, or third-party material.

Frames are written as PPM, compressed to baseline JPEG by `cjpeg`, and piped as MJPEG to FFmpeg, which encodes VP8 into WebM with a keyframe every second, single-threaded, with bit-exact container flags and no metadata.

Generation command, run from `apps/web/`:

```sh
CJPEG=/opt/homebrew/opt/jpeg-turbo/bin/cjpeg \
FFMPEG=~/Library/Caches/ms-playwright/ffmpeg-1011/ffmpeg-mac \
npm run test-media
```

Tools used: libjpeg-turbo 3.2.0 `cjpeg` and Playwright's bundled FFmpeg `n7.0.1-playwright-build-1011`, on macOS 26.6.2. Two consecutive runs produced byte-identical files. Other tool versions may produce different bytes; the committed files and the digests above are authoritative.

### Why WebM and VP8

The generation toolchain available when these files were made, Playwright's bundled FFmpeg, encodes only VP8 into WebM. VP8 in WebM plays in the Playwright Chromium build the tests use and exercises the same player code as any other format.

The files have no audio track, so they do not exercise audio decoding or any audio-specific autoplay restriction.

## MP4 fixture

### Why it exists

Driftless's later media direction targets MP4 containing H.264/AVC video and AAC audio. This fixture adds that media shape to local-player qualification, alongside the VP8/WebM files, so the player is exercised with a second container and codec pair and with an audio track. It is a local playback fixture only.

### Provenance

`synthetic-320x180-8s-h264-aac.mp4` was generated by [`scripts/generate-test-media-mp4.mjs`](../../scripts/generate-test-media-mp4.mjs) from FFmpeg's built-in generators: `testsrc2` (a moving test pattern with a frame counter) for the picture and `sine` (a 440 Hz tone) for the sound. It contains no recorded, personal, or third-party material.

FFmpeg encodes H.264 with libx264 (High profile, level 3.0, a keyframe every second, 2 B-frames, single-threaded, about 100 kb/s) and AAC-LC with its native encoder (stereo, 48 kHz, 64 kb/s), and writes an MP4 with the index (`moov`) before the media data, bit-exact flags, and no metadata.

Generation command, run from `apps/web/`:

```sh
FFMPEG=/path/to/node_modules/ffmpeg-static/ffmpeg npm run test-media:mp4
```

Tools used: the `ffmpeg-static` 5.3.0 npm package's FFmpeg 6.0 binary for macOS arm64 (SHA-256 `a90e3db6a3fd35f6074b013f948b1aa45b31c6375489d39e572bea3f18336584`, x264 core 164 r3075), installed outside the repository with `npm install --save-exact ffmpeg-static@5.3.0`, on macOS 26.6.2. It is not a dependency of this package. Playwright's bundled FFmpeg cannot produce this file because it has no H.264 encoder. Two consecutive runs produced byte-identical files. Other FFmpeg builds may produce different bytes; the committed file and the digest above are authoritative.

### Inspection

`ffmpeg -hide_banner -i synthetic-320x180-8s-h264-aac.mp4` with the same binary reports:

```text
major_brand     : mp42
compatible_brands: mp42iso2avc1mp41
Duration: 00:00:08.00, start: 0.000000, bitrate: 185 kb/s
Stream #0:0: Video: h264 (High) (avc1), yuv420p(progressive), 320x180 [SAR 1:1 DAR 16:9], 110 kb/s, 30 fps
Stream #0:1: Audio: aac (LC) (mp4a), 48000 Hz, stereo, fltp, 64 kb/s
```

An MP4Box.js 2.4.1 parse, run outside the repository, reports top-level boxes `ftyp moov free mdat` and no fragmentation. The video track is `avc1.64001e`, 240 samples over 8.000 s, 8 of them sync samples. The audio track is `mp4a.40.2`, 2 channels at 48 kHz, 376 samples over 8.021 s. Each track has one edit-list entry with `media_time` 1024.
