# Spike 0.6 MSE Progressive Playback Experiment

This page plays a **locally selected** MP4 (H.264 + AAC) through Media Source Extensions (MSE). It supplies the media incrementally, so playback starts while most segments have not been appended yet. The media is local. A deterministic scheduler simulates progressive arrival; nothing here is network streaming.

```text
local File → bounded File.slice() reads → Spike 0.5 moov parse + deterministic plan
  → cut one keyframe-aligned fMP4 segment (video + audio fragments), verify it
  → simulated arrival (FAST / NORMAL / SLOW / BURSTY / MANUAL)
  → per-SourceBuffer append queue (never appends while updating)
  → MediaSource → HTMLVideoElement
```

This is laboratory code only. It contains no WebRTC, peer transfer, OPFS or other storage, synchronization, or Progressive Watch implementation. The page's Content Security Policy sets `connect-src 'none'` and allows `media-src` only for `blob:` (the page's own MediaSource URL). There is no analytics or telemetry.

## Layout

| File | Responsibility |
| --- | --- |
| `src/preparer.mjs` | Opens a local MP4 once and cuts planned segments on demand. It reuses the Spike 0.5 pre-check, classification, segment plan, source reader, and fMP4 verifier by importing them unchanged. It builds combined and per-track init segments, cuts segment *k* from one bounded window, and refuses any fragment that fails verification. |
| `src/append-queue.mjs` | State machine around one `SourceBuffer`. It serialises `appendBuffer()`/`remove()` behind `updating`/`updateend`, handles `error`/`abort`, handles `QuotaExceededError` (evict or defer), clears the queue on seek, and releases bytes after use. |
| `src/delivery.mjs` | Deterministic release profiles, the release scheduler (initial burst, hold/resume/release, gating, urgent release on seek), and `SegmentState`, which tracks the next segment needed from the playhead. |
| `src/pipeline.mjs` | Wires the parts together. It owns the MediaSource lifecycle, the lookahead gate, back-buffer trimming, seek classification and reprioritisation, end-of-stream, failure handling, event and stall recording, and full teardown with a resource report. |
| `src/diagnostics.mjs` | Bounded timeline, append log, and samples; tracking of object URLs, timers, listeners, and frame callbacks; safe formatting. |
| `src/ranges.mjs` | `TimeRanges` snapshots and comparisons (containment, ahead, growth, loss). |
| `src/scenarios.mjs` | Scripted experiments MSE-01 to MSE-12, supplementary observations S1 to S4, an unload probe, and a native-playback control. |
| `src/app.mjs` | Page controller: manual controls, buffer visualization, the experiment runner, and `pagehide` teardown. |
| `src/*.test.mjs`, `src/test-fakes.mjs` | Node unit and integration tests. The fakes include a `SourceBuffer` that enforces the `updating` contract, and fake timers. |

## Dependencies

There is no new dependency. The page and tests import MP4Box.js 2.4.1 and the Spike 0.5 modules from `../spike-05-mp4-segmentation/`. Install Spike 0.5's pinned copy first:

```sh
(cd spikes/phase0/spike-05-mp4-segmentation && npm ci --ignore-scripts)
```

## Run

From the repository root:

```sh
python3 -m http.server 4177 --bind 127.0.0.1 --directory spikes/phase0
```

Open `http://127.0.0.1:4177/spike-06-mse-progressive/`, select a file, and then either:

- press **Load** and **Play**, and drive it by hand with **Hold**, **Release**, **Seek**, the delivery profile, and **Reset**; or
- choose a scripted experiment and press **Run experiment**. Its bounded JSON evidence appears under **Experiment result**.

Playback starts only after a click on the page. The browser's autoplay policy is left in force.

## Experimental Parameters (not production values)

| Parameter | Value |
| --- | --- |
| Segment plan | Spike 0.5 deterministic plan, ≈ 2 s target, GOP-bounded |
| Read block (metadata) | 1 MiB; one read in flight; one bounded window per segment (≤ 64 MiB) |
| Delivery profiles | FAST 8×, NORMAL 1.5×, SLOW 0.5× real time; BURSTY: 4 segments at 6×, then a pause of 3 segment durations; MANUAL |
| Initial segments | 2 by default |
| Lookahead cap | 60 s of media ahead of the playhead, including in-flight segments |
| Back buffer | 30 s behind the playhead, trimmed with `remove()` with 10 s hysteresis |
| Prepared ahead | 2 segments cut in advance, not yet "delivered" |
| Append backpressure | Delivery pauses while any queue has ≥ 4 queued operations or is blocked |
| Quota handling | Evict up to 2 s behind the playhead and retry; otherwise defer 1 s. At most 30 attempts per append |

These values are laboratory parameters. They are not proposed startup, low-water, or high-water thresholds, and the profiles do not model any Internet condition.
